# SPEC-capture: A1580 settings as a typed model and a readable YAML file

Decision (made by the project owner): test conditions for the pulser-receiver are
written as YAML files in `captures/`, validated by a typed Python model that is the single
source of truth for keys, choices, units and ranges, with a JSON schema generated from
that model for editor completion. The plug applies them through `apply_setup()`.

## 1. The model (`capture.py`)

Top-level `Capture` dataclass with these groups (all groups optional; an omitted group
emits nothing for that group, so a file can set only what it cares about). Every field
is optional too; only set fields are emitted. Ranges and choices come from `PROTOCOL.md`;
where it says UNKNOWN, do not invent a limit, accept any value of the right type.

| Group / field | YAML type | SCPI header | Notes |
|---|---|---|---|
| `sampling.rate` | `'100 MHz'` | `FREQ` | choices 1, 2, 5, 10, 25, 50, 100 MHz only |
| `sampling.length` | int 1024..36864 | `DATA:LENG` | |
| `mode` | `'master'` or `'slave'` | `MODE` | emits `MASTer` / `SLAVe` |
| `pulser.enabled` | bool | `TRAN:ENAB` | emitted **last** of all headers |
| `pulser.type` | `'single'` or `'dual'` | `TRAN:TYPE` | |
| `pulser.reverse_polarity` | bool | `TRAN:REV` | |
| `pulser.voltage` | `'20 V'` 5..100, multiple of 5 | `TRAN:PULS` | |
| `pulser.frequency` | `'2.5 MHz'` 10 kHz..20 MHz | `TRAN:FREQ` | emit in kHz like the vendor: `2500 KHZ` |
| `pulser.periods` | number 0.5..16, multiple of 0.5 | `TRAN:DUR` | |
| `pulser.gap` | `'5 ns'` 0..500, multiple of 5 | `TRAN:GAP` | |
| `pulser.damping` | bool | `TRAN:DAMP` | |
| `pulser.damping_gap` | `'30 ns'` 10..500, multiple of 5 | `TRAN:DAMP:GAP` | |
| `pulser.impedance` | `'high'`, `'200'`, `'1000'` (strings) | `TRAN:IMP` | |
| `receiver.gain` | `'10 dB'` 0..80 | `GAIN` | |
| `receiver.preamp_combined` | bool | `GAIN:PRE:COMB` | |
| `receiver.preamp_split` | bool | `GAIN:PRE:SPLIT` | |
| `receiver.high_pass` | `'1 kHz'`, `'100 kHz'`, `'500 kHz'`, `'1 MHz'` | `FILT:HPAS:IND` | emits index 0..3 |
| `receiver.tgc.mode` | `'off'`, `'linear'`, `'arbitrary'` | `GAIN:TGC:MODE` | emitted after the curve |
| `receiver.tgc.linear` | `{offset: '20 us', slope: '0.1 dB/us'}` | `GAIN:TGC:LIN` | emits `20.0, 0.1` |
| `receiver.tgc.arbitrary` | list of `{time: '10 us', gain: '5 dB'}` | `GAIN:TGC:ARB` | emits `10,5,20,10`; times must be strictly increasing |
| `trigger.mode` | `'internal'`, `'ctp'`, `'encoder'`, `'ttl'` | `TRIG:MODE` | |
| `trigger.interval` | `'10 ms'` 100 us..10 s | `TRIG:INT` | emit in `US` |
| `trigger.delay` | `'15 us'` 0..2147483647 ns | `TRIG:DEL` | emit in `NS` |
| `averaging.count` | int 0..8 | `AVER:COUN` | semantics UNKNOWN, document that in the field help |
| `averaging.constant_delay` | `'auto'` or `'10 us'` | `AVER:DEL:CONS:AUTO` + `AVER:DEL:CONS` | `'auto'` emits `AUTO ON`; a value emits `AUTO OFF` then the value in `NS` |
| `averaging.random_delay` | `'2 us'` 0..32767 ns | `AVER:DEL:RAND` | emit in `NS` |
| `extra` | mapping header -> string | as given | appended before `TRAN:ENAB`, never validated |

Quantity spellings: a string with a number, optional space, and a unit from the set the
field allows (`Hz kHz MHz`, `V`, `dB`, `ns us ms s`, `dB/us`). Case as written, but also
accept `KHZ`/`khz` etc. A bare number where a quantity is expected is an error that says
which unit to add. Cross-checks: a `tgc.mode` of `linear` or `arbitrary` without the
matching curve is an error; `sampling.length` must be a multiple of 1 (just an int);
`pulser.voltage` above 50 V is allowed but `check` prints a one-line warning
(the owner wants high voltage to be a conscious choice).

`Capture.to_scpi() -> dict[str, str]` returns an insertion-ordered dict of header ->
argument string, headers in the vendor example's spelling, order: sampling, mode,
pulser (without enable), receiver, trigger, averaging, extra, then `TRAN:ENAB` last.
`Capture.describe() -> str` gives a one-line human summary for logs.

`load_capture(path) -> Capture`, `parse_capture(text, *, source='<string>') -> Capture`,
`capture_schema() -> dict`, and `apply_capture(plug, capture_or_path, *, reset=False)`
which loads and validates **before** anything is sent, optionally calls `plug.reset()`,
then `plug.apply_setup(capture.to_scpi())`. `reset` defaults to False here (unlike the
sibling) because `*RST` defaults are UNKNOWN on this device. The plug agent will later
add a one-line `A1580Plug.apply_capture` that delegates to this function; you only need
the function, tested against the fake via `A1580Plug(resource=FakeA1580Resource())` if
`plug.py` exists when you run your tests, otherwise against a stub with `apply_setup`.

CLI: `python -m a1580_openhtf.capture schema` prints the schema (and `--write` writes
`capture.schema.json`), `python -m a1580_openhtf.capture check <files>` validates and
exits 1 on problems. `captures/vendor_example.yaml` starts with the two schema pointer
comment lines (see sibling's `captures/clock.yaml`) and reproduces the vendor example
(`PROTOCOL.md` "Vendor example call sequence") with the pulser at 20 V.

## 2. Tests (`tests/test_capture.py`)

1. `vendor_example.yaml` loads; `to_scpi()` equals the expected ordered dict (write it out
   in the test), with `TRAN:ENAB` last.
2. A `MISTAKES` parametrised table of at least 15 `(name, yaml, key_path, message_fragment, line)`
   cases: unknown key with suggestion, bare number, wrong unit, out-of-range voltage,
   voltage not a multiple of 5, non-listed sampling rate, tgc mode without curve,
   non-increasing arbitrary times, duplicate key, unquoted `off` for a choice, wrong type,
   impedance given as a number, unknown trigger mode, negative delay, length too large.
3. `tests/data/broken.yaml` reports all its problems in file order, with line numbers.
4. Committed `capture.schema.json` equals `capture_schema()`; it validates with
   `jsonschema.Draft202012Validator`; every `Literal` choice list in the model equals the
   schema's enum.
5. `apply_capture` of a broken file writes nothing to the fake's `log`; of the vendor
   example it produces the expected write sequence.
6. CLI `check` on a good and a broken file (subprocess, exit codes, message on stderr),
   `schema --write` round trip in `tmp_path`.
7. `mypy --strict` clean on `capture.py` (run it; it is part of Done).
